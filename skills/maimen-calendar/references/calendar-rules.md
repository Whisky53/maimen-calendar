# 日历规则（maimen-calendar）

本文件收纳 SKILL.md 中移出的规则细节。实现见 `scripts/`。

---

## 1. 天气分层标准

数据源：中国天气网（实时 + 今日 + 生活指数）。MCP 无天气能力，属自行接入。

### 温度四层

| 区间 | 档位 | 饮食建议倾向 |
| --- | --- | --- |
| ≤ 5°C | 严寒 | 强烈偏热饮、热食、暖胃 |
| 5–15°C | 偏凉 | 偏热饮 |
| 15–28°C | 舒适 | 温度不限 |
| 28–35°C | 偏热 | 偏冷饮 |
| ≥ 35°C | 酷热 | 强烈偏冷饮、补水 |

### 降水

识别轻/中/重三档（`precipLevelOf`），雨雪天转为偏热倾向。

### 空气质量

AQI 三档；差时提示减少外出。

### 风力与紫外线

- 风级：支持 `<3级` 这类写法（正则含 `<` 分支）
- 紫外线：强时提示防晒

### 冲突消解

多个信号冲突时，**权重高者主导，弱者转备注**，不静默丢弃。

## 2. 活动力度评分（5 档）

评分是**启发式估算**，不是官方优惠金额。实际优惠以麦当劳官方渠道为准。

| 档位 | 阈值 | 标识 | 日历行为 |
| --- | --- | --- | --- |
| 大力 | ≥ 80 | 🔥 | 单独建活动事件（10:00） |
| 值得去 | ≥ 60 | ✨ | 单独建活动事件（10:00） |
| 小惊喜 | ≥ 35 | 🙂 | 不单独建事件，写进当日提醒描述 |
| 平平 | ≥ 18 | 💤 | 同上 |
| 无活动 | < 18 | 😐 | 同上 |

### 关键规则

- **往年/往期活动完全忽略**（`isPastDay`），不进 TOP、不进推荐
- 内容型活动（联合款、上新）权重**适度降低**，避免纯联名日虚高
- 「加价换购」单列计分，不与折扣叠加重复计分
- 裸「专属」字样不单独计分，需含 `会员日|会员专享|会员价`
- 花式数字（`𝟗` = U+1D7D7）需经 `normalizeDigits()` 归一后才能识别
- TOP 榜有 `recommendFloor` 下限（20 分），低分日不进 TOP
- 同一天多活动去重

### 力度 → 偏好倾向

| 档位 | prefTrend | 说明 |
| --- | --- | --- |
| 大力 | 1.5 | 同预算内可优先尝鲜款 |
| 值得去 | 1.2 | 同预算内优先活动款 |
| 小惊喜 | 1.0 | 常规 |
| 平平 | 0.9 | 走性价比 |
| 无活动 | 0.8 | 常规款 |

> ⚠️ `prefTrend` **只影响排序倾向，不影响预算**。
> 预算为硬上限，任何档位都不放大（需求说明书 §13.2）。

## 3. 提醒与日历（§8）

### UID 规则

```
<userScope>-<planId>-<date>-<slot|instance>-<type>@maimen.local
```

| 段 | 含义 | 示例 |
| --- | --- | --- |
| `userScope` | 用户范围 | `local` |
| `planId` | 计划标识 | `default` |
| `date` | 发生日期 | `2026-10-10` |
| `slot` | 餐次或提醒实例 | `breakfast` / `lunch` / `training` |
| `type` | 事件类型 | `meal` / `reminder` / `training` / `campaign` |

**禁止**使用列表序号或标题构造 UID —— 否则重排后客户端会「新增一条」而非「更新一条」。

由此保证：

- 同日早餐与晚餐 UID **不同**，可共存（AC-34）
- 同一餐次的提醒与事件本身 UID **不同**
- 列表顺序变化不影响 UID

### 更新机制

更新已存在事件时：

- **保留 UID**
- `SEQUENCE` 递增（默认 0）
- 刷新 `LAST-MODIFIED` 与 `DTSTAMP`
- 取消的事件写 `STATUS:CANCELLED`，**且不再带 VALARM**

### 事件合并规则（§8.3）

导出前调用 `mergeSchedule()`：

| 规则 | 行为 |
| --- | --- |
| 同一天的「活动信息」 | 并入当天**第一个用餐事件**的 description，不再单独建事件 |
| 不同餐次 | **绝不合并**（同日早餐与晚餐保持两条） |
| 同一 `date+slot` 重复出现 | 按 `date+slot` 去重，重复刷新不产生重复事件 |
| 当天没有用餐事件（餐次被关闭） | 保留独立活动事件，不丢弃 |

合并**与顺序无关**：活动排在用餐事件之前或之后都能正确并入。

### 提醒设置（§8.1）

持久化到 `~/.maimen/reminders.json`（可用 `MAIMEN_REMINDERS_PATH` 覆盖）。

| 能力 | 命令 |
| --- | --- |
| 首次设置（确认餐次/时间/时区/重复规则） | `--setup-reminders --slots breakfast,lunch` |
| 查看当前设置 | `--view-reminders` |
| 修改某餐次 | `--slot-config lunch --remind-lunch 11:45` |
| 开启 / 关闭某餐次 | `--slot-config dinner --disable` |
| 重复规则 | `--repeat daily\|weekdays\|custom --repeat-days 1,2,3` |
| 暂停全天 | `--pause --until 2026-10-07` |
| 恢复 | `--resume` |
| 跳过某天 | `--skip-day 2026-10-06 [--slot lunch]` |
| 延后本次 | `--snooze lunch --minutes 45` |

**关键要求**：

- 每个餐次**独立开关**，不默认开启全部餐次
- 首次设置需确认；已有明确要求**不重复确认**（只做增量合并）
- 日程生成时用 `shouldRemind()` 过滤：未开启 / 暂停 / 跳过 / 不在重复日 / 已延后 → 不生成
- 已保存的提醒设置**优先于**命令行 `--slots`；未做持久设置时回落到 `--slots`

> ⚠️ **「周一至周五」不等于法定工作日。**
> `weekdays` 规则只表示星期一至星期五。调休上班日与法定节假日
> **必须有可靠日历来源或用户自定义**（`holidays` / `customWorkdays`），
> 本工具**不做假定**，输出时会明示这一点。

### 三种交付状态（§8.2）

提醒的交付必须如实说明「能承诺什么、不能承诺什么」，
**不得用文本承诺替代后台能力**：

| 交付方式 | 可承诺 | 不可承诺 |
| --- | --- | --- |
| **ICS 文件** | 文件已生成，含事件与提醒设置 | 已添加进你的日历；一定会弹窗提醒 |
| **日历订阅** | 订阅地址可用，内容可更新 | 所有客户端实时刷新；秒级撤销 |
| **宿主调度工具** | 工具确认已创建定时任务 | 不具备后台能力时关闭应用也会运行 |

导入后是否弹窗、何时弹窗取决于用户所用日历客户端设置；
宿主是否支持后台触发取决于宿主能力。这两点必须说清楚，不能含糊。

### 提醒时间建模

提醒时间与事件开始时间**分别建模**：

- 事件开始时间 = 餐次/训练的计划时间
- 提醒提前量 = `alarmMinutes`（VALARM `TRIGGER:-PT<n>M`）

各餐次默认提醒时间：

| 餐次 | 默认时间 |
| --- | --- |
| 早餐 | 07:30 |
| 午餐 | 11:30 |
| 加餐 | 15:00 |
| 晚餐 | 18:30 |
| 夜宵 | 22:00 |

可用 `--remind-<slot>` 逐餐次覆盖；`--remind` 仅在单餐次时有效。

### 跨午夜

夜宵时段跨到次日（22:00–04:59），`inferSlot` 已处理；
生成事件时 `date` 取提醒实际发生日，不因跨午夜而错位。

### iCalendar 规范（RFC 5545）

- 行以 CRLF 分隔
- 长行按 75 字节折行
- 文本转义 `\` `;` `,` 与换行
- 内嵌 `VTIMEZONE`（Asia/Shanghai）
- 提醒用 `VALARM`

## 4. 热量与训练

### 热量

- 数据源：麦当劳官方营养表（`list-nutrition-foods`，约 160 条）
- 返回是**紧凑文本表格**，需专门解析（字段序：名称, 描述, kJ, kcal, 蛋白, 脂肪, 碳水, 钠, 钙）
- 名称模糊匹配需容错（去括号、去空格、包含匹配）

**关键约束（§13.2）**：

> 单餐热量缺失时**保留 unknown**，不按 0 参与全天计算，且**不输出全天收支结论**。

`balance()` 在 `intakeKcal` 为 null 时直接返回 `verdict: "unknown"` 与说明，
`netKcal` 保持 null。

### 训练

- 内置模板：`fatLoss` / `muscle` / `maintain`
- 消耗按 MET 表估算（10 种运动）
- BMR 用 Mifflin-St Jeor；TDEE = BMR × 活动系数

### 参数语义（§13.2，不可混淆）

| 参数 | 含义 | 取值 |
| --- | --- | --- |
| `--training` | 训练计划模板 | `fatLoss` / `muscle` / `maintain` |
| `--goal` | 每日热量目标 | 数值 kcal |

写错直接报错退出，不静默忽略。
