# 麦门日历 · 麦门午饭与训练管家

把「天气 → 活动力度 → 吃什么 → 热量 → 训练 → 日历」串成一条闭环。
核心一句话：**每天中午不用再想，日历已经替你想好了。**

## 何时使用本 Skill

- 「今天吃什么 / 中午吃啥」——结合天气、活动力度、预算、热量给建议。
- 「最近哪几天麦当劳活动力度大 / 什么时候去吃最划算」——活动力度评分。
- 「帮我把麦当劳活动同步到日历 / 导个提醒」——生成 .ics 或订阅链接。
- 「这餐多少卡 / 我今天吃了多少」——热量摄入计算。
- 「帮我排个训练计划 / 今天练什么」——训练计划 + 热量收支平衡。

## 设计原则（不可违背）

1. **只提醒，绝不自动下单**：本 Skill **不调用** `create-order`，不支付、不扣积分、不自动领券。日历事件里明确写"请自行前往官方渠道下单"。
2. **不下结论式的健康判断**：热量与训练消耗均标注为**估算**，不做医疗/营养诊断，不替代专业建议。
3. **力度是估算**：活动力度评分是启发式规则（关键词 + 事件类型 + 券数），**不是官方优惠金额**，输出必须注明。
4. **硬约束优先**：预算、忌口等约束不被天气/星座/活动力度突破。
5. **数据来源可追溯**：每条输出都能说明来自「中国天气网」还是「麦当劳 MCP」还是「本地默认」。

## 快速开始

```bash
cd scripts

# 1) 今日建议（天气 + 活动力度 + 预算 + 推荐）
node cli.mjs --city 上海 --budget 40

# 2) 未来 7 天规划 + 导出日历文件
node cli.mjs --city 上海 --budget 40 --days 7 --ics ./maimen.ics

# 3) 加训练计划 + 热量目标
node cli.mjs --city 北京 --budget 45 --training fatLoss --weight 58 --goal 1600

# 4) 启动订阅服务（日历自动同步）
MCD_MCP_TOKEN=xxx node serve.mjs --city 上海 --budget 40 --training fatLoss --port 8899

# 5) 离线演示（不联网）
node cli.mjs --demo --city 上海

# 6) 回归测试
node test.mjs
```

## 日历接入方式（需求 4）

### 方式 A：导出 .ics 文件（最简单，全平台通吃）

```bash
node cli.mjs --city 上海 --days 30 --ics ./maimen.ics
```

得到 `.ics` 后双击即可导入：
- **苹果日历（iOS/macOS）**：双击 → 自动打开日历 App → 选择日历 → 导入
- **谷歌日历**：设置 → 导入和导出 → 选择文件 → 导入
- **Outlook**：文件 → 打开和导出 → 导入/导出 → 导入 iCalendar
- **系统日历（Windows/Linux）**：双击或拖入

### 方式 B：订阅链接（自动更新）

```bash
MCD_MCP_TOKEN=xxx node serve.mjs --city 上海 --budget 40 --training fatLoss --port 8899
```

然后添加订阅：
- **苹果日历**：`webcal://127.0.0.1:8899/maimen.ics`（文件 → 新建日历订阅）
- **Outlook**：`http://127.0.0.1:8899/maimen.ics`
- **谷歌日历**：同样地址，**但需要公网可访问**（本机地址谷歌拉不到）

刷新间隔默认 6 小时，可用 `--refresh <分钟>` 调整。

## 天气标准（需求 1 的"标准"）

温度分层规则，可通过 `weatherPolicy(w, thresholds)` 自定义阈值。
**2026-10-10 优化：二分 → 四层，并新增降水强弱 / 风力 / 紫外线 / 冲突消解。**

| 条件 | 默认阈值 | 权重 | 影响 |
| --- | --- | --- | --- |
| 严寒 | `tempC ≤ 5` | w3 | 强烈建议热食热饮 |
| 偏凉 | `5 < tempC ≤ 15` | w2 | 优先热食热饮 |
| 舒适 | `15 < tempC < 28` | w1 | 温度不限 |
| 偏热 | `28 ≤ tempC < 35` | w2 | 优先冰饮清爽 |
| 酷热 | `tempC ≥ 35` | w3 | 强烈建议冰饮清爽 |
| 降水·强 | 暴雨/雷阵雨/大雨/暴雪 | w2 | 偏向暖胃、汤食类 |
| 降水·弱 | 小雨/小雪/阵雨 | w1 | 偏向暖胃、汤食类 |
| 空气·差 | `AQI ≥ 150` | w2 | 建议减少外出、优先堂食或外送 |
| 空气·轻度 | `100 ≤ AQI < 150` | 备注 | 敏感人群可考虑外送 |
| 大风 | `windLevel ≥ 6` | 备注 | 外带体验打折，建议堂食 |
| 紫外线 | `uv = strong` | 强化 | 高温时强化冰饮倾向，常温时给防晒提示 |

**冲突消解**：多个温度倾向矛盾时（如「37°C + 暴雨」），取权重高者主导，弱者降级为备注
（输出为 `kind: "note"` 信号），避免上层推荐拿到互相打架的信号。

已收录城市：北京、上海、广州、深圳、杭州、成都、武汉、南京、西安、重庆、天津、苏州、长沙、郑州、青岛。
其他城市可直接传 9 位城市码（`--city 101020100`）。

## 活动力度评分说明（需求 2）

评分 0–100，**启发式**，由三部分构成：

1. **优惠型活动**（权重高）：命中「免单 / 买一送一 / 半价 / X元套餐 / 会员价 / 满减」等关键词。
   - ⚠️ **加价换购**（"加 39.9 元即可得周边"）只按低权重 8 分计，且会让「明确标价」让位，
     避免"多花 39.9 元"被当成"省了 39.9 元"重复计分。
2. **内容型活动**（权重低，**封顶 15 分**）：上新 / 联名 / 周边 / 线下派对等——**有变化但不省钱**。
3. **门店券**：`query-store-coupons` 返回的可用券数量（每张 +5，上限 +24）。

**三重防刷分机制**（均由实测踩坑后加入）：
- **花式数字归一化**：麦当劳文案常用数学粗体数字（`𝟗.𝟗元` = U+1D7D7），普通正则完全匹配不到，
  先归一化全角/粗体/粗斜体/等宽四类数字，并把 `13.9r` → `13.9元`。
- **同日去重**：同一天内按归一化标题去重，同一活动多条只算一次。
- **跨天降权**：同一活动只在首次出现日计全分，之后出现降权 `×(1 - ratio×0.65)`。
- **往期剔除**：`dateText` 含「往期/回顾/已结束」的日期不进入推荐，避免推荐已结束的活动。

力度档位（**5 档，2026-10-10 重设**）：

| 档位 | 阈值 | 含义 |
| --- | --- | --- |
| 🔥 大力 | ≥ 80 | 超级活动日（多活动 + 券叠加） |
| ✨ 值得去 | ≥ 60 | 明确的低价活动 |
| 🙂 小惊喜 | ≥ 35 | 有点优惠或多个内容活动 |
| 💤 平平 | ≥ 18 | 只有单个内容活动 |
| 😐 无活动 | < 18 | 基本没活动，按常规吃 |

> 设计要点：**事件多 ≠ 力度大**。全部是"上新/联名"的日子不会被评成"大力"，
> 因为它只代表菜单有变化，不代表更省钱。这是实测中修正过的一个关键误判。

力度还会反馈到预算策略（`levelToBias`）：大力日 1.15 倍放宽预算，值得去 1.08 倍，
平平/无活动则走性价比路线。推荐只在 ≥20 分的「够格日」里挑选（`recommendFloor`），
低分日不塞进 TOP，避免"矮子里拔将军"。

## 热量与训练（需求 5、6）

- **热量数据**：来自麦当劳官方营养表（`list-nutrition-foods`，实测 160 条），含能量 kcal/kJ、蛋白质、脂肪、碳水、钠、钙。
- **训练消耗**：MET 公式估算 `MET × 体重(kg) × 时长(h)`，支持跑步/骑行/游泳/力量/HIIT/球类等 10 种。
- **热量收支**：`摄入 − 消耗 = 净`，与目标（TDEE 或你指定的 `--goal`）对比，给出盈余/平衡/超标判断。
- **训练模板**：`fatLoss`（每周 4 次）/ `muscle`（每周 4 次）/ `maintain`（每周 3 次），可展开到任意日期区间。

> ⚠️ 热量与消耗**均为估算**，不构成医疗或营养建议。

## 模块结构

```
scripts/
  cli.mjs        主入口：串联天气 → 活动 → 预算/热量 → 训练 → 日程 → 导出
  weather.mjs    中国天气网适配（实时/预报/生活指数）+ 温度分层规则

  mcd.mjs        麦当劳 MCP 适配层（含活动日历、券、营养表解析）
  test.mjs       回归测试（71 项，离线可跑）
references/
  data-sources.md  数据源与接口实测记录
```
